# FindTrail 2.1

FindTrail 2.1 makes repeated searches meaningfully faster without turning the app into an organizer, account system, or chatbot.

## Release behavior

- A found place can be saved as an item's intentional home. That home appears before learned guesses on future trails.
- Custom items can be pinned as compact shortcuts on the home screen.
- A successful search records both the exact found place and the trail stop where it was found. Repeatedly successful trail stops move earlier next time.
- Finishing a trail without finding the item shows practical next actions tailored to the item and its urgency.
- All local data can be exported to and restored from a validated FindTrail JSON backup.
- An installed app announces when a new version is ready and lets the person choose when to reload.
- Share previews and install metadata use the established field-guide visual system and approved tagline: “A calmer path to what’s missing.”

## Ordering rules

1. Urgent safety action, when applicable
2. Saved home spot
3. Exact place learned from previous finds
4. Search area learned from successful trails
5. Clue-driven and item-default stops
6. Slow final sweep

## Data and privacy

- Storage migrates from version 2 to version 3 in place without deleting valid history or an active trail.
- Backups contain only the data already stored in the browser.
- Restore replaces local FindTrail data only after validation and explicit confirmation.
- No account, analytics, remote database, advertising, or location tracking is added.
